# 멀티모달 기반 위험행동 감지 시스템

**Multimodal Risk Behavior Detection System**

영상 행동과 입력 행동 정보를 결합한 **온라인 시험 부정행위 의심행동 탐지 시스템**입니다.
웹캠에서 관찰한 고개·시선·얼굴 행동과 키보드·붙여넣기·활성 창의 행동 정보를 함께 분석하는 멀티모달 시스템입니다.
의심 사건을 기록하고 **감독관이 근거를 확인하여 조치**하도록 지원합니다.

영상 특징 추출에는 사전 학습된 MediaPipe 얼굴 모델을 사용합니다. 영상·입력 사건의 결합과 점수 계산은
시간 연관 조건 및 규칙에 기반합니다. 두 입력을 함께 학습한 단일 멀티모달 AI 모델을 구현한 것은 아닙니다.

현재 검증 대상은 Windows 코드 시험입니다. 기존 실행 프로필은 독립 실행형 CBT에도 사용할 수 있습니다.
점수는 부정행위 확정·확률·검증된 탐지 정확도를 뜻하지 않습니다.

## 실행과 검토

1. `run.cmd` 실행 → 시험 환경 선택 → 시작 안내와 타이핑 기준 설정.
2. 지정한 시험 앱과 웹캠 감시가 함께 시작됩니다. 정면 보정을 완료합니다.
3. 미검토 누적 점수가 기준에 도달하면 감독관 창이 비동기로 열립니다. **시험과 감시는 계속됩니다.**
4. 감독관이 사건을 선택해 ID·발생 시각·지속시간·가중치·신뢰계수·기여점수·결합 근거를 확인합니다.
5. 이름·판단·사유를 입력하고 **판단 저장 · 조치 적용**을 누릅니다.

현재 `.venv\Scripts\python.exe`를 사용합니다. VS Code에서도 이 인터프리터를 선택하세요.

```powershell
.\.venv\Scripts\python.exe main.py
```

기존 앱 아이콘만 여는 것은 감시 시작으로 연결되지 않습니다. 이 실행기를 통해 시험 앱을 시작해야 합니다.
단독 ESC 또는 감시 창 X는 사용자의 실행 종료이며, 그때 관리 중인 시험 앱도 정리됩니다.
Ctrl+Shift+Esc는 단독 ESC로 취급하지 않습니다. q는 종료 키가 아닙니다.
R 키는 얼굴 재보정입니다. 누적 점수와 검토 완료 지점을 초기화하지 않습니다.
코드를 수정하기 전에 시작한 실행에는 새 코드가 반영되지 않으므로 종료 후 다시 시작하세요.

## 서로 다른 세 가지 값

| 값 | 의미 |
|---|---|
| 현재 위험도 R | 최근 20초 사건 기여점수에 반감기 9초 감쇠를 적용한 보조 표시 |
| 세션 누적 검토 점수 C | 채택된 새 사건의 가중치 × 신뢰계수를 ID별로 한 번씩 합산 |
| 검토 완료 지점 B | 감독관이 명시적으로 계속 응시를 결정한 검토 범위 끝의 C |

`R = Σ(기여점수 × 2^(-사건 경과초 / 9))`, 사건 경과가 20초를 넘으면 R 계산에서 제외합니다.
`C = Σ(새 사건 기여점수)`, `미검토 = C - B`, `C - B >= T`이면 확인 대기입니다.

- `config.py`의 `review_threshold` 기본값은 **100**입니다. 50은 검증용 예시입니다. 둘 다 개발 기준입니다.
- R의 NORMAL/WATCH/SUSPICIOUS 표시는 호출 여부와 독립적입니다. 정상 자세로 돌아가 R이 줄어도 C와 확인 대기는 유지됩니다.
- C에는 100 상한이 없습니다. 120·250도 저장하고 표시합니다. 그래프 축은 실제 R/C에 맞춰 확장합니다.
- 매 프레임의 R 또는 지속 행동 하한을 C에 합산하지 않습니다. 지속시간과 반복 간격을 충족해 생성된 사건만 채택합니다.
- 원본 사건 ID, 파생 복합 사건의 원본 ID 쌍, CSV 기록 ID를 기준으로 재처리 중복을 방지합니다.
- 새 실행 또는 명시적인 재시험만 새 세션 ID와 C=0, B=0으로 시작합니다.

예: T=50, C=48에서 21초 기다리면 R은 0이 되어도 C는 48입니다.
새 사건이 3점을 기여하면 C=51이 되어 즉시 호출됩니다.

## 감독관 확인 대기와 조치

| 판단 | 동작 |
|---|---|
| 판단 보류 | 사유 저장, 기존 확인 대기와 B 유지 |
| 계속 응시 | 사유·검토 범위 저장, 그 범위의 C까지만 B 진행. 시험과 감시는 계속 |
| 시험 중단 결정 / 퇴장 조치 결정 | 판단 저장 후 이번 실행의 관리 대상 프로그램 종료 |
| 재시험 요청 | 이전 세션·판단 보관 후 같은 프로필로 새 시작 안내 → 새 세션·새 로그·0점 |

창을 닫거나 새로고침하는 것은 검토 완료가 아닙니다. 닫힌 창은 매 프레임 다시 생성하지 않으며
확인 대기는 감시 화면과 CSV에 남습니다. 다시 열 때는 `reviewer.cmd`를 사용합니다.

판단 목록에서 ‘계속 응시’를 고르는 것만으로는 적용되지 않습니다. 이름·사유를 입력하고
‘판단 저장 · 조치 적용’을 누른 뒤 ‘판단 적용 완료’ 응답을 확인하세요.
B는 검토 범위의 C로 자동 갱신되며 직접 입력하지 않습니다.
자동 검토창은 보관 CSV를 읽되 현재 감시기의 CSV 경로를 `--control-log`로 별도 전달받습니다.
판단과 요청은 프로젝트의 reviews / review_commands 폴더로 보내며 sessions 하위에 보내지 않습니다.

창을 열었을 때 **이번 검토 범위**를 고정합니다. 새 근거는 목록에 **[미포함]**으로 실시간 추가됩니다.
단순 새로고침은 이 범위를 진행하지 않습니다. 새 사건도 검토하려면
**새 근거까지 검토 범위에 포함**을 누르고 확인하세요.
‘계속 응시’는 고정 범위만 완료합니다. 검토 중 생긴 사건이 T 이상 남으면 재알림합니다.
기존 창이 살아 있으면 그 창을 갱신하고 앞으로 표시하며, 새 창을 여러 개 만들지 않습니다.
이미 검토 완료한 범위의 반복 완료 요청은 거부합니다.
판단 이력은 오른쪽 **판단 이력** 탭에 표시합니다.

## 행동 가중치

아래는 신뢰계수를 곱하기 전 개발 가중치입니다.

| 관찰 / 행동 | 기본 모드 | 테스트 모드 |
|---|---:|---:|
| Ctrl+C/X/V, Shift+Insert, Alt+Tab, Win+Tab | 0 | 0 |
| PrintScreen, Win+Shift+S | 0 | 0 |
| 지속된 비허용 창 이탈 | 8 | 14 |
| LARGE_PASTE 80–199자 | 8 | 15 |
| LARGE_PASTE 200–499자 | 12 | 15 |
| LARGE_PASTE 500자 이상 | 18 | 15 |
| 영상·입력 복합 행동 | 10 | 12 |
| 타이핑 속도·리듬·급입력 이상 단독 | 0 | 0 |
| 타이핑 이상 + 확인된 영상 이상 또는 최근 창 이탈 | 사건당 최대 2 | 사건당 최대 2 |

기본 붙여넣기 구간은 `event_weights["LARGE_PASTE"]`의 1 / 1.5 / 2.25배입니다.
최소 크기 기본값은 `large_paste_chars=80`입니다.
기존 붙여넣기 신뢰계수 `min(1, 0.5 + 문자수/400)`를 유지하므로,
80자 기본 가중치 8의 실제 기여는 5.6점입니다. 가중치와 실제 기여를 CSV에 따로 기록합니다.

Ctrl+V/Shift+Insert와 LARGE_PASTE가 같은 입력에서 생겨도 단축키 기여는 0입니다.
0점 단축키는 영상과 겹쳐도 복합 점수를 만들지 않습니다.
Ctrl+T/N/L/W, Ctrl+Shift+T/I/Esc, Alt+F4, F12는 의심 단축키 감지와 가중치에서 제거했습니다.

복합 점수는 **5초 이내 실제 영상 사건과 LARGE_PASTE 또는 WINDOW_FOCUS_LOST 사건**을 연결합니다.
복합 이벤트 재발생 제한은 **4초**이며 결합된 사건 ID 두 개를 저장합니다.
확인된 영상 상태만 있고 연결할 실제 사건이 없는 경우 복합 점수를 만들지 않습니다.
타이핑 보조 사건에는 10/12점 복합 점수를 추가하지 않습니다.

LARGE_PASTE는 **붙여넣기 단축키를 눌렀을 때 클립보드 규모를 확인한 관찰**입니다.
실제 삽입 성공이나 외부 코드 출처를 확인한 것이 아닙니다.
허용된 자기 코드 재사용도 점수화됩니다. 이 정상 시나리오의 한계를 테스트에 명시했습니다.

고개·시선·얼굴 감지 조건, 보정 방식, 복수 얼굴 감지 코드는 이번 변경에서 유지했습니다.
실제 적용되는 영상 가중치는 `config.py`의 기본/테스트 가중치 표를 참고하세요.

## 실행 프로필과 허용 창

`exam_profiles.json`에 환경을 보관합니다. 기존 GUI에서 환경을 추가·선택합니다.
실행 파일은 Windows의 실제 `.exe`, 작업 폴더는 기존 디렉터리, 실행 옵션은 한 줄에 인수 하나입니다.
`{python}`, `{project}`, `{session_dir}` 변수를 실행 경로·옵션에 사용할 수 있습니다.
VS Code는 `--new-window --user-data-dir <이번 세션 폴더>`로 독립 실행합니다.
IPython 환경은 선택한 Python에 IPython이 설치되어 있어야 합니다.

- 이번에 실행한 앱과 그 자식 프로세스의 창은 허용합니다.
- `window_keywords`는 이 관리 대상 앱의 창을 제목으로 더 제한하는 기존 설정입니다.
- 외부 문제 페이지·별도 터미널은 프로필의 `allowed_windows`에 **실행 파일 절대경로와 특정 제목 키워드**를 함께 등록합니다.
- 허용 창은 종료 대상이 아닙니다. 종료 대상은 여전히 이번 시험에서 실행한 프로세스 트리뿐입니다.
- GUI에서 기존 프로필을 저장해도 `allowed_windows` 규칙은 보존됩니다. 이 규칙은 현재 JSON에서 편집합니다.

프로필 내부 예시(경로와 제목은 실제 환경에 맞춰 변경):

```json
"allowed_windows": [
  {
    "executable": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe",
    "title_keywords": ["교내 시험 문제 - 1회차"]
  },
  {
    "executable": "C:\\Windows\\System32\\cmd.exe",
    "title_keywords": ["시험용 터미널"]
  }
]
```

클릭으로 이동해도 창 감시가 작동합니다. 처음 허용 창을 확인한 뒤 감시를 시작하고,
비허용 창에 2초 머물면 사건을 만들며 계속 머물면 10초 간격으로 반복합니다.
허용 IDE·문제 페이지·터미널 전환은 창 이탈 점수를 만들지 않습니다.

**범위 한계:** 제목과 실행 경로는 웹 URL·페이지 내용의 진위를 증명하지 않습니다.
너무 넓은 제목 키워드를 쓰면 다른 페이지도 허용될 수 있습니다.
기존 브라우저에 연결하고 종료되는 실행기, 웹 CBT 서버의 시험 상태, 원격 앱, WSL/VM은 별도 연동이 필요합니다.
Ubuntu용 프로필·프로세스 그룹 실행 구조는 유지하지만 Linux 창 감시 어댑터는 미구현입니다.
현재 이 작업에서 검증한 운영체제는 Windows입니다.

## 감독관과 응시자의 로컬 입력 구분 한계

자동으로 연 감독관 프로세스가 전면에 있으면 그 창의 키 입력, 붙여넣기, ESC와 창 이탈 체류시간을
응시자 점수에서 제외합니다. 입력 리듬도 그 시간 때문에 급입력으로 오인되지 않도록 정리합니다.
이미 누적된 사건·점수는 지우지 않습니다. 해당 창으로 이동/복귀한 사실은 0점 시스템 로그로 남깁니다.

카메라 감시는 계속됩니다. 감독관이 카메라에 들어오거나 응시자가 감독관을 바라보는 상황을
자동 구분하지 못하며 영상 사건이 발생할 수 있습니다. 같은 PC의 실제 조작자가 누구인지,
감독관 이름이 진짜인지 인증하는 기능도 없습니다.
`reviewer.cmd`로 별도 실행한 수동 창은 자동 실행 프로세스와 동일한 제외 대상으로 확인되지 않습니다.
따라서 현재 로컬 시제품의 운용 검증에는 이러한 상황을 포함해야 합니다.
독립 감독관 계정·별도 장치·원격 권한 제어는 이번 범위에 포함하지 않았습니다.

## 기록과 추적

- `anti_cheating_events.csv`: 현재 실행 기록.
- `sessions/<세션ID>_<시각>.csv`: 실행마다 별도 파일, 실행 중에도 같은 기록을 추가.
- `exam_runs/<세션ID>/profile.json`: 적용한 실행 프로필.
- `reviews/<세션ID>/<검토ID>/decision.json`: 감독관 이름·판단·사유·검토 범위.
- 같은 검토 폴더의 `reviewed_events.csv`: 실제 검토한 스냅샷과 SHA-256.
- `control_result.json`: 해당 세션에 대한 조치 처리 결과.
- `review_commands/<세션ID>/`: 세션에 한정한 요청과 응답.

CSV는 기존 11개 열에 SessionId, EventId, EventSequence, Weight, CumulativeScore,
ReviewedScore, ReviewedThrough, ReviewPending, ReviewThreshold, RelatedEventIds를 추가합니다.
RiskScore는 R, CumulativeScore는 C, ReviewedScore는 B입니다.
ScoreContribution은 실제로 한 번 가산한 기여점수입니다.
시스템·관찰 사건은 0점이며, 검토 호출·완료·판단 사건이 범위와 사유를 연결합니다.
SCORE_STATUS는 1초마다 R/C/B/대기 상태를 기록하되 점수를 더하지 않습니다.
누적값 100 초과를 정상적으로 읽습니다. 이전 11열 CSV도 열 수 있으며 C/B를 복원했다고 표시하지 않습니다.

키 입력 문자·클립보드 원문·창 제목·카메라 프레임은 CSV에 저장하지 않습니다.
새 실행과 재시험 전에 이전 CSV가 보관되어 덮어쓰기로 사라지지 않습니다.
기존 작업용 VS Code 등은 이름으로 찾아 종료하지 않습니다. Windows Job 소유권으로 관리합니다.
제어 요청은 같은 세션의 저장된 판단·근거 해시·검토 범위가 일치해야 처리합니다.
이는 로컬 실수·세션 혼선을 방지하는 검증이며 파일 변조 방지 보안 체계는 아닙니다.

## 검증과 재현

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe tools\simulate_scenarios.py
.\.venv\Scripts\python.exe -m pip check
```

테스트는 임시 디렉터리의 합성 사건·판단·CSV 및 테스트용 프로세스를 사용합니다.
실제 사용자 기록과 웹캠·전역 키보드 훅을 사용하지 않습니다.
시뮬레이션 결과는 `validation/review_policy_trace.csv`와
`validation/review_policy_scenarios.json`에 저장합니다.
기존 개발 검증 보고서는 로컬 `validation/` 폴더에 보관합니다. GitHub에는 소스와 테스트를 공개하고,
실행별 출력과 로컬 검증 보고서는 포함하지 않습니다. 위 명령으로 현재 환경에서 다시 검증하세요.

이 검증은 **기다리기 회피 방지와 구현 동작 검증**입니다.
실제 응시자 데이터에 대한 오탐률·미탐률·탐지 정확도는 측정하지 않았습니다.
점수·신뢰계수·T=50/100을 검증된 탐지 성능 기준으로 해석하면 안 됩니다.

## 새 PC 환경 준비

Python 3.12와 Git이 설치된 Windows 환경에서 다음 명령을 실행합니다. 같은 환경에 OpenCV 배포판을 여러 개 설치하지 마세요.

```powershell
git clone https://github.com/thdtmdwo3301/capstone.git
cd capstone
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
```

설치 후 `run.cmd`를 실행합니다. `face_landmarker.task`가 없으면 첫 감시 시작 시
`config.py`의 `MODEL_URL`에 지정된 Google MediaPipe 배포 주소에서 자동 다운로드합니다.
첫 다운로드에는 인터넷 연결이 필요하며, 이후에는 프로젝트 폴더에 저장된 모델을 사용합니다.

`exam_profiles.json`은 PC별 실행 경로를 담는 로컬 설정이므로 GitHub에서 제외합니다.
파일이 없으면 VS Code·IPython 기본 프로필을 제안합니다. 시험 환경 선택 창에서
실행 파일과 작업 폴더를 확인하고 저장하세요. 일반 CBT 프로그램도 이 창에서 추가할 수 있습니다.

가상환경, 모델, 시험 작업 파일, CSV, 감독관 판단, 세션 기록과 백업은 `.gitignore`로 제외합니다.
이 파일들은 사용자 PC에 계속 보관됩니다. 카메라 접근·키보드 훅·대상 앱의 실제 동작은 사용 PC에서 확인해야 합니다.
